Overview

Nemo's engine, a new shell around it

FileHarbor is a fork of Nemo, the file manager of the Cinnamon desktop. Nemo already does the hard parts well: browsing, remote locations, thumbnails, file operations. I kept that engine and changed what surrounds it, so the everyday jobs that usually send you to another app happen in a tab next to your files.

It follows the desktop's light or dark mode and accent colour with square, COSMIC-style corners, and everything it adds is optional: each built-in tool can be switched off in the appearance settings and the file manager falls back to Nemo's own behaviour.

Base Nemo 6.8.3
Stack C, GTK 3, Python tools
Role Solo: design, build, packaging

What it adds

Everything is a tab

Embedded terminal

A panel that follows the folder you are in, with a toolbar toggle. Focus stays in the terminal when the path changes.

Text editor

Syntax highlighting for about 170 languages, search and replace, minimap, 19 colour themes and Prettier formatting.

Markdown and MDX

Live preview beside the editor, 19 preview themes, MDX components, and a collapse button for the editor pane.

Image editor

Rotate, crop, resize, adjust, remove a plain background, camera RAW, plus batch resize and convert.

Media player

Video and music open in a tab, with trim, convert, extract audio and GIF maker.

Storage page

A disk-usage view of your drives and folders, so you see what fills them.

Developer tools

File hashes, JSON and text helpers and more, from a Tools page and the context menu.

Themes and extensions

A live theme editor, remote-connection dialogs and an extension system for your own pages.

Screenshots

Files, terminal and tools in one window

Double-click a file and its tool opens as a new tab and takes focus.

Engineering challenges

What was hard, and what I learned

01

Tools as tabs inside a C application

Problem

Nemo is C and GTK. I wanted the editor, image and media tools in Python, but as real tabs in the file manager, not separate windows.

Approach

Embed CPython, build each tool as a GTK widget, and hand the widget back to C as a virtual view. The same pages also run standalone, which kept them easy to test.

02

Focus that stays where you put it

Problem

When the terminal changes directory, the file view reloads and pulled keyboard focus away mid-typing. Opening a file in a new tab could also lose the switch to it.

Approach

Guard the focus calls when the terminal owns focus, and defer the tab switch until the old tab's own focus handling has finished.

03

Dialogs and popup menus on Wayland

Problem

A modal dialog started from inside a popup menu's own click handler is fragile on Wayland and can take the app down.

Approach

Open the dialog a moment after the menu has closed, so the toolkit never has two grabs in flight.

04

Shipping a fork that replaces a system package

Problem

FileHarbor owns Nemo's binary, libraries and D-Bus names, and has Python and WebKit dependencies of its own.

Approach

An Arch package that provides and conflicts with nemo, a Flatpak manifest, and a release workflow that builds both and updates the AUR when a production version is published.
